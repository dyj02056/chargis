# OPEN_ISSUES — 사용자 결정/확인 필요 항목

## 10/28 설명회에서 확인할 것 (plan.md §14)
> 2026-10-25에 Pleos 공식 문서(document.pleos.ai)로 답이 나온 항목은 `docs/DECISIONS.md`에 옮겼다. 아래는 문서에 없거나 문서끼리 어긋나는 것만 남겼다.

1. 공공 충전소 데이터 사용 가능 여부, 호출 방식, 키 발급, 호출 제한, 앱 번들 허용 여부, 앱의 외부 서버(중계 서버) 호출 허용 여부
2. TTS·STT SDK: 사용 신청 문서에는 "준비 중(Coming Soon)"인데 SDK 문서에는 사용법(On-device 모드는 등록 불필요)이 있다. 공모전 개발 기간에 쓸 수 있는지, 언제 풀리는지
3. 탑재 차종 목록과 차종별 배터리 용량·전비·충전 성능 공식 출처(Vehicle SDK의 CarInfo는 VIN·CRN만 준다)
4. 참고자료 GitHub 링크의 계정 이름(사용자 ID)도 "계정정보 노출"에 해당하는지, 해당하면 조직·별도 계정으로 옮겨야 하는지. 제출 규칙의 APK 파일명 `팀명_앱이름_release.apk`가 개인 참가면 실명이 되는데 이름 없이 내도 되는지, 비공개 저장소용 심사 계정은 언제 공지되는지
5. 주행 가능 거리 조회 API가 있는지(문서에는 `setRangeRemainingDistance`만 있다)
6. Mobility Services 카테고리로 Distraction Optimization을 선언하면 주행 중 카드 화면(큰 버튼 2개)이 허용되는지, 공모전 시연에서도 카테고리·DO 심사 기준을 따르는지
7. 동승석 화면 지원 여부

## 제출 규칙에 맞출 것 (참가 가이드 · 지원·제출 방법)
- APK는 저장소 `apk/` 폴더에 release 빌드로 올린다. 지금 `.gitignore`가 `*.apk`를 막는다. 파일명은 위 4번 답을 듣고 정한다.
- README에 APK 파일 위치를 적는다(필수 항목: 앱 이름·한 줄 소개, 실행 방법, 테스트 환경·설정, APK 위치).
- 숏폼 설명란에 필수 해시태그 `#HMG차량용앱개발공모전` 포함 2~3개, CC BY 효과음 2개 출처 표기.
- 수정 제출 시 전체 자료와 서명한 동의서를 다시 첨부하고 제목 앞에 `[수정제출]`을 붙인다.

## 사용자 결정 필요
- Pleos Connect 에뮬레이터: Android Studio SDK Manager의 SDK Update Sites에 Pleos Connect System Image(API 34, v2.1.0)를 추가해 설치한다(설치 방법은 DECISIONS 2026-10-25). Android Studio가 필요하다.
- 현재 화면 확인은 일반 Android 에뮬레이터(`chargis_wide`, API 35 태블릿 가로형)로만 했다. Pleos Connect 에뮬레이터에서 다시 확인해야 하고, 앱 창이 1개·2개로 나뉘는 세로 레이아웃도 확인해야 한다.
- 시연 영상 구성: F3 제한 알림은 S3 시나리오에서만 나온다. 3분 영상에 S1과 S3를 어떻게 나눠 담을지 결정이 필요하다.
- 순정 내비가 이미 충전 계획(추천 충전소, 목표 SoC, 충전 시간)을 낸다. 신청서·README의 차별점을 시간 제한·혼잡 비교·동승자 화면·휴게소 밖 대안 쪽으로 다시 쓸지 정해야 한다.
- 공공 충전소 API 키를 발급받으면 `scripts/check-public-api.ps1`로 실제 응답 필드를 한 번에 점검할 수 있다. 실제 응답 필드(statId, chgerType, output, stat, limitYn/limitDetail, kind/kindDetail, useTime, parkingFree, note 등)가 어댑터 가정과 맞는지 확인해야 한다. 특히 ① limitDetail이 이용자 제한 사유인지(시간 제한 문구가 들어오는 경우가 있는지), ② 시설 구분 코드표(C001/C002/C003 등)와 빼기로 한 20개 소분류가 맞는지, ③ 휴게소 충전기의 시간 제한이 어느 필드에 오는지 확인한다. 공공데이터에 없으면 운영기관 공지에서 확인한 규칙을 출처와 함께 `assets/charger_rules.json`에 적는다(`getChargerOperatorInfo`는 사업자 id·이름만 준다). 지금은 비어 있어 실제 데이터에서는 시간 제한이 "정보 없음"으로 나온다. ④ `busiId`(운영기관 아이디)가 목록 API에도 오는지 확인한다.
- 경로 폴리라인·고도는 NaviHelper에 없다. 직선 투영과 우회 어림(직선 옆 거리 × 1.3)은 `requestTrip(좌표)`가 주는 실제 도로 거리·도착 시간·도착 SoC로 바꿀 수 있다. 후보마다 호출하므로 호출 횟수와 응답 시간을 에뮬레이터에서 재 봐야 한다. 반대 방향 휴게소는 여전히 이름의 "(○○방향)"으로 거른다.
- 경유지는 최대 2개다. 운전자가 이미 경유지를 넣어 둔 경우 Chargis가 쓸 자리가 줄어든다. 두 자리가 다 찼을 때 어떻게 안내할지 정해야 한다.
- 휴게소 밖 충전소의 가정값(진출입 5분, 휴게소 아닌 곳 순위 가산 5분, 경로 이탈 기준 편도 0.5km, 도착 후 30분 영업, 20km마다 2곳)과 추천 계산 간격(0.5km·30초)은 실제 주행 자료와 차량 기기 성능으로 다듬어야 한다. 휴게소만 보고 싶은 운전자는 설정 "충전소 범위 → 휴게소·쉼터만"으로 끌 수 있다.
- 공공데이터 시도 코드: 강원·전북은 특별자치도 출범 뒤 코드(51, 52)로 넣었다. API가 옛 코드(42, 45)를 쓰는지 실제 응답으로 확인해야 한다. 시도 경계는 중심점 거리로 어림하므로(점마다 가까운 두 시도), 필요보다 조금 많이 받는다.
- 공공데이터 중계 서버(`server/charger-proxy.mjs`)를 어디에 띄울지(클라우드 함수, 작은 VM 등)와 HTTPS 주소를 정해야 한다. data.go.kr 일일 호출 한도에 맞춰 저장 시간을 다듬어야 하고, 사용자가 늘면 공용 캐시가 필요하다.
- 음성 명령(AndroidSpeechStt)은 아직 마이크 입력으로 확인하지 못했다. Pleos 에뮬레이터는 마이크 접근 설정을 지원하므로 거기서 확인한다. TTS가 말하는 동안 인식기가 그 소리를 듣지 않는지도 봐야 한다.
- 충전구 타입 코드 08(DC콤보 완속)·09(NACS)·10(DC콤보+NACS)과 상태 응답의 마지막 충전 종료 시각(`lastTedt`)이 실제 API에 오는지 확인해야 한다. 오지 않으면 고장 의심 표시는 데이터가 없어 나오지 않는다.
- 공공데이터와 `getChargerOperatorInfo` 모두 요금이 없다. 운영기관별 급속 단가를 출처와 함께 `assets/charger_rules.json`에 적을지(요금 변경 때마다 갱신 필요) 정해야 한다. 지금은 실제 데이터에서 요금이 "정보 없음"이다.
- 배터리 온도와 예열 제어는 Vehicle SDK에 없고, 차량 제어 SDK는 "준비 중"이다. 실차에서는 바깥 기온으로 어림하고 예열은 "차량 화면에서 켜 주세요" 안내만 할 수 있다. [배터리 예열 켜기] 버튼을 남길지(누르면 안내만 나옴) 뺄지 정해야 한다. 온도 계수(`BatteryThermal`)는 차종별 실측으로 다듬어야 한다.
- 충전 출력(kW)은 Vehicle SDK에 없다. 충전 중 남은 시간은 지금처럼 SoC 증가율과 충전 곡선 모델로 계산하고, 화면의 "지금 들어오는 kW"는 추정값임을 표시해야 한다.
- 배터리 직접 입력은 데모에서만 확인했다. 실차에서 계기판 값과 추정이 얼마나 벌어지는지, 정차 화면의 [맞음]과 버튼 4개가 충분한지 사용자 확인이 필요하다.
- 스크린샷은 2026-10-25에 22장 모두 다시 찍었다(일반 Android 에뮬레이터). Pleos Connect 에뮬레이터 이미지로 시연 영상을 찍기 전에 한 번 더 확인한다.
- 개인정보 점검(`scripts/check_privacy.sh`): 2026-10-25에 로컬 패턴을 채워 돌렸다. 파일 내용에는 없고, 첫 커밋(GitHub 웹에서 만든 Initial commit)의 작성자에 계정 이름이 남아 있다. 위 설명회 질문 4번 답에 따라 처리한다.
