# OPEN_ISSUES — 사용자 결정/확인 필요 항목

## 10/28 설명회에서 확인할 것 (plan.md §14)
1. Vehicle SDK로 받을 수 있는 항목(SoC, 주행가능거리, 기어/속도, 충전 상태·출력), 권한 승인 절차, 에뮬레이터 제공 여부
2. NaviHelper `addWaypoint` 후 `requestReRoute` 호출 순서/제약, 경로 폴리라인 조회 가능 여부
3. `getChargerOperatorInfo`로 얻는 정보 범위(사업자, 출력, 규칙, 실시간 상태)
4. 공공 충전소 데이터 사용 가능 여부, 호출 방식, 키 발급, 호출 제한, 앱 번들 허용 여부
5. 에뮬레이터 해상도/폼팩터, 동승석 화면 지원 여부, 앱 마켓 입점 시 주행 중 UI 규정
6. TTS/STT SDK 제약(발화 우선순위, 주행 중 허용 규정)
7. 탑재 차종 목록과 차종별 배터리 용량·전비·충전 성능 공식 출처

## 사용자 결정 필요
- Pleos Connect 에뮬레이터 이미지(AVD) 설치: 공모전 제공 이미지를 받아 Android Studio에 등록해야 에뮬레이터 시연이 가능하다.
- `scripts/check_privacy.sh`의 검사 패턴(실명·전화번호·이메일)을 로컬에서 채워야 한다.
- 현재 화면 확인은 일반 Android 에뮬레이터(`chargis_wide`, API 35 태블릿 가로형)로만 했다. Pleos Connect 에뮬레이터 이미지에서 다시 확인해야 한다.
- 시연 영상 구성: F3 제한 알림은 S3 시나리오에서만 나온다. 3분 영상에 S1과 S3를 어떻게 나눠 담을지 결정이 필요하다.
- 공공 충전소 API 키를 발급받으면 `scripts/check-public-api.ps1`로 실제 응답 필드를 한 번에 점검할 수 있다. 실제 응답 필드(statId, chgerType, output, stat, limitYn/limitDetail, kind/kindDetail, useTime, parkingFree, note 등)가 어댑터 가정과 맞는지 확인해야 한다. 특히 ① limitDetail이 이용자 제한 사유인지(시간 제한 문구가 들어오는 경우가 있는지), ② 시설 구분 코드표(C001/C002/C003 등)와 빼기로 한 20개 소분류가 맞는지, ③ 휴게소 충전기의 시간 제한이 어느 필드에 오는지 확인한다. 공공데이터에 없으면 운영사 정보(`getChargerOperatorInfo`)나 운영기관 공지에서 확인한 규칙을 출처와 함께 `assets/charger_rules.json`에 적는다(지금은 비어 있어 실제 데이터에서는 시간 제한이 "정보 없음"으로 나온다). ④ `busiId`(운영기관 아이디)가 목록 API에도 오는지 확인한다.
- 내비 SDK에서 경로 폴리라인을 받으면 직선 투영을 바꾼다. 반대 방향 휴게소는 이름의 "(○○방향)"으로 임시로 걸러 내지만(방향 표기가 없거나 표에 없는 도시면 못 거른다), IC에서 들어가기 어려운 국도변 충전소는 가려내지 못하고, 우회 거리도 직선 옆 거리 × 1.3으로 어림한다. 실제 경로에서 충전소까지 도로 거리(왕복)를 받을 수 있는지 확인해야 한다.
- 내비 SDK에 경유지 삭제 기능이 있는지 확인해야 한다. 수락한 경유지를 더 빠른 곳으로 바꿀 때 `NaviPort.removeWaypoint`로 이전 것을 지운다(SDK 스텁은 아직 실패를 돌려준다).
- 휴게소 밖 충전소의 가정값(진출입 5분, 휴게소 아닌 곳 순위 가산 5분, 경로 이탈 기준 편도 0.5km, 도착 후 30분 영업, 20km마다 2곳)과 추천 계산 간격(0.5km·30초)은 실제 주행 자료와 차량 기기 성능으로 다듬어야 한다. 휴게소만 보고 싶은 운전자는 설정 "충전소 범위 → 휴게소·쉼터만"으로 끌 수 있다.
- 공공데이터 시도 코드: 강원·전북은 특별자치도 출범 뒤 코드(51, 52)로 넣었다. API가 옛 코드(42, 45)를 쓰는지 실제 응답으로 확인해야 한다. 시도 경계는 중심점 거리로 어림하므로(점마다 가까운 두 시도), 필요보다 조금 많이 받는다.
- 공공데이터 중계 서버(`server/charger-proxy.mjs`)를 어디에 띄울지(클라우드 함수, 작은 VM 등)와 HTTPS 주소를 정해야 한다. data.go.kr 일일 호출 한도에 맞춰 저장 시간을 다듬어야 하고, 사용자가 늘면 공용 캐시가 필요하다.
- 음성 명령(AndroidSpeechStt)은 에뮬레이터에서 마이크 입력으로 확인하지 못했다. 실기기나 Pleos STT SDK에서 확인이 필요하다. TTS가 말하는 동안 인식기가 그 소리를 듣지 않는지도 봐야 한다.
- 충전구 타입 코드 08(DC콤보 완속)·09(NACS)·10(DC콤보+NACS)과 상태 응답의 마지막 충전 종료 시각(`lastTedt`)이 실제 API에 오는지 확인해야 한다. 오지 않으면 고장 의심 표시는 데이터가 없어 나오지 않는다.
- 공공데이터에는 요금이 없다. 운영기관별 급속 단가를 출처와 함께 `assets/charger_rules.json`에 적을지(요금 변경 때마다 갱신 필요), 운영사 정보(`getChargerOperatorInfo`)로 받을 수 있는지 정해야 한다. 지금은 실제 데이터에서 요금이 "정보 없음"이다.
- 배터리 온도·예열: Vehicle SDK로 배터리 온도와 예열 상태를 읽을 수 있는지, 앱에서 예열을 켤 수 있는지 확인해야 한다. 못 읽으면 바깥 기온으로 어림하고, 못 켜면 "차량 화면에서 켜 주세요" 안내만 한다. 온도 계수(`BatteryThermal`)는 차종별 실측으로 다듬어야 한다.
- 고도: 내비 SDK가 경로 고도(또는 폴리라인)를 주는지 확인해야 한다. 주지 않으면 실제 경로에서는 평지로 계산한다. 차량 무게·회생 효율은 차종별 값이 필요하다.
- 배터리 직접 입력은 데모에서만 확인했다. 실차에서 계기판 값과 추정이 얼마나 벌어지는지, 정차 화면의 [맞음]과 버튼 4개가 충분한지 사용자 확인이 필요하다.
- 주행 중 화면의 [배터리 예열 켜기] 버튼이 Pleos 앱 마켓의 주행 중 조작 규정에 맞는지 확인해야 한다. 허용되지 않으면 버튼을 빼고 음성 명령 "예열"만 남긴다.
- 스크린샷은 2026-10-25에 22장 모두 다시 찍었다(일반 Android 에뮬레이터). Pleos Connect 에뮬레이터 이미지로 시연 영상을 찍기 전에 한 번 더 확인한다.
