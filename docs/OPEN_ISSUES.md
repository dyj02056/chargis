## 사용자 결정 필요
- **실제 주행 모드(나중에 보완):** 지금은 하이브리드 데모다(경로·시계·충전 진행은 시뮬레이터, 차량 신호·경유지는 Pleos SDK). 순정 내비에 설정한 목적지·경로·현재 위치로 여행을 시작하는 "실제 주행" 표를 추가하려면, `TripController`가 직접 쓰는 시뮬레이터(시계, 차종, 충전 진행, 저장·복원)를 "여행 진행원" 인터페이스로 떼어 내고 실시간 시계·차량 SoC·설정 차종으로 움직이는 구현을 더해야 한다. 실제 경로 위 충전소는 공공데이터 키(debug) 또는 중계 서버가 있어야 하고(설명회 질문 1), 그때는 `RoadDistanceRefiner`가 위치 일치 조건을 만족해 실제 도로 거리를 쓴다.
- 순정 내비 경유지: 2026-10-26에 내비 목적지(속초시)를 정한 뒤 수락해, 내비가 "경유지 1개 포함"으로 B 휴게소를 거쳐 다시 탐색하는 것을 확인했다. 경유지 두 자리가 다 찼을 때의 안내와 경유지 교체(이전 것 삭제)는 단위 테스트로만 확인했다.
- 순정 내비의 도착 배터리 예측(`estimatedSocAtDest`, 경로 화면의 도착 %)이 Virtual Console의 Battery SOC(60%)와 맞지 않는다(가까운 휴게소 도착 90%). 내비가 어느 값으로 배터리를 보는지(Battery Energy·Capacity 등) 확인이 필요하다. 지금은 이 값을 쓰지 않는다.
- 에뮬레이터 위치: `adb emu geo fix`로 바꿔도 내비 현재 위치는 수정구 시흥동(37.4127, 127.0947)에 그대로다. 그래서 가상 경로 데모에서는 차 위치가 경로와 맞지 않아 `requestTrip` 보정이 꺼져 있다(의도대로). 실제 주행 모드를 시험하려면 내비 위치를 움직이는 방법(Virtual Console 주행·경로 시뮬레이션 등)을 찾아야 한다.
- 경유지 추가 위치: 비어 있으면 첫째 자리, 하나 있으면 둘째 자리에 넣는다. 운전자가 넣은 경유지보다 충전소가 앞에 있으면 순서가 바뀔 수 있다.
- 화면 확인: 2026-10-28에 Pleos Connect 에뮬레이터에서 S1~S6을 돌렸다(DECISIONS). 실제 분할 창(앱 2개 동시 표시)은 아직 Pleos 에뮬레이터에서 확인하지 않았다. 스크린샷 22장은 여전히 일반 에뮬레이터에서 찍은 것이다.
- 시연 영상: Pleos 에뮬레이터 원본 녹화(S1 전체 + S3 제한 장면, 2배속 6분, 소리 없음)를 `video/demo/`에 두었다. 제출용으로는 3분 안팎으로 자르고, 자막이나 안내 음성(녹화에 소리가 담기지 않음)을 덧붙여야 한다.
- 수락 후 순정 내비가 앞으로 나온다: 순정 내비에 목적지가 없을 때 [경유지로 수락]을 누르면 내비 화면이 앞으로 나와 Chargis가 뒤로 간다(2026-10-28 Pleos 에뮬레이터). 목적지가 있으면 경유지를 넣고 다시 탐색한다. 운전자가 앱으로 돌아오지 않아도 음성 안내는 계속 나오지만, 목적지가 없으면 경유지를 넣지 않고 안내만 할지 정해야 한다.
- S3에서 E 휴게소에 도착했을 때 오른쪽 "앞으로의 충전소" 표가 비어 있었다(S1의 B 휴게소에서는 나옴). 남은 후보가 F 하나뿐이라서인지 확인해야 한다.
- 공공 충전소 API 키를 발급받으면 `scripts/check-public-api.ps1`로 실제 응답 필드를 한 번에 점검할 수 있다. 실제 응답 필드(statId, chgerType, output, stat, limitYn/limitDetail, kind/kindDetail, useTime, parkingFree, note 등)가 어댑터 가정과 맞는지 확인해야 한다. 특히 ① limitDetail이 이용자 제한 사유인지(시간 제한 문구가 들어오는 경우가 있는지), ② 시설 구분 코드표(C001/C002/C003 등)와 빼기로 한 20개 소분류가 맞는지, ③ 휴게소 충전기의 시간 제한이 어느 필드에 오는지 확인한다. 공공데이터에 없으면 운영기관 공지에서 확인한 규칙을 출처와 함께 `assets/charger_rules.json`에 적는다(`getChargerOperatorInfo`는 사업자 id·이름만 준다). 지금은 비어 있어 실제 데이터에서는 시간 제한이 "정보 없음"으로 나온다. ④ `busiId`(운영기관 아이디)가 목록 API에도 오는지 확인한다.
- 경로 폴리라인·고도는 NaviHelper에 없다. 차 위치가 경로와 맞으면 가까운 3곳은 `requestTrip`의 실제 도로 거리로 바꾼다(`RoadDistanceRefiner`, 60초 캐시, 위치 조회는 10초 간격). 응답 시간과 실제 경로에서의 정확도는 실제 주행 모드에서 재 봐야 한다. 반대 방향 휴게소는 여전히 이름의 "(○○방향)"으로 거른다.
- 휴게소 밖 충전소의 가정값(진출입 5분, 휴게소 아닌 곳 순위 가산 5분, 경로 이탈 기준 편도 0.5km, 도착 후 30분 영업, 20km마다 2곳)과 추천 계산 간격(0.5km·30초)은 실제 주행 자료와 차량 기기 성능으로 다듬어야 한다. 휴게소만 보고 싶은 운전자는 설정 "충전소 범위 → 휴게소·쉼터만"으로 끌 수 있다.
- 공공데이터 시도 코드: 강원·전북은 특별자치도 출범 뒤 코드(51, 52)로 넣었다. API가 옛 코드(42, 45)를 쓰는지 실제 응답으로 확인해야 한다. 시도 경계는 중심점 거리로 어림하므로(점마다 가까운 두 시도), 필요보다 조금 많이 받는다.
- 공공데이터 중계 서버(`server/charger-proxy.mjs`)를 어디에 띄울지(클라우드 함수, 작은 VM 등)와 HTTPS 주소를 정해야 한다. data.go.kr 일일 호출 한도에 맞춰 저장 시간을 다듬어야 하고, 사용자가 늘면 공용 캐시가 필요하다.
- 음성 명령은 Pleos SpeechToText SDK(On-device, 폴백은 AndroidSpeechStt)로 옮겼지만 아직 마이크 입력으로 확인하지 못했다. Pleos 에뮬레이터의 마이크 접근 설정을 켜고 확인한다. TTS가 말하는 동안 인식기가 그 소리를 듣지 않는지도 봐야 한다.
- 충전구 타입 코드 08(DC콤보 완속)·09(NACS)·10(DC콤보+NACS)과 상태 응답의 마지막 충전 종료 시각(`lastTedt`)이 실제 API에 오는지 확인해야 한다. 오지 않으면 고장 의심 표시는 데이터가 없어 나오지 않는다.
- 공공데이터와 `getChargerOperatorInfo` 모두 요금이 없다. 운영기관별 급속 단가를 출처와 함께 `assets/charger_rules.json`에 적을지(요금 변경 때마다 갱신 필요) 정해야 한다. 지금은 실제 데이터에서 요금이 "정보 없음"이다.
- 배터리 온도와 예열 제어는 Vehicle SDK에 없고, 차량 제어 SDK는 "준비 중"이다. 실차에서는 바깥 기온으로 어림하고 예열은 "차량 화면에서 켜 주세요" 안내만 할 수 있다. [배터리 예열 켜기] 버튼을 남길지(누르면 안내만 나옴) 뺄지 정해야 한다. 온도 계수(`BatteryThermal`)는 차종별 실측으로 다듬어야 한다.
- 충전 출력(kW)은 Vehicle SDK에 없다. 충전 중 남은 시간은 지금처럼 SoC 증가율과 충전 곡선 모델로 계산하고, 화면의 "지금 들어오는 kW"는 추정값임을 표시해야 한다.
- 배터리 직접 입력은 데모에서만 확인했다. 실차에서 계기판 값과 추정이 얼마나 벌어지는지, 정차 화면의 [맞음]과 버튼 4개가 충분한지 사용자 확인이 필요하다.
- 스크린샷은 2026-10-25에 22장 모두 다시 찍었다(일반 Android 에뮬레이터). Pleos Connect 에뮬레이터 이미지로 시연 영상을 찍기 전에 한 번 더 확인한다.
- 개인정보 점검(`scripts/check_privacy.sh`): 2026-10-25에 로컬 패턴을 채워 돌렸다. 파일 내용에는 없고, 첫 커밋(GitHub 웹에서 만든 Initial commit)의 작성자에 계정 이름이 남아 있다. 위 설명회 질문 4번 답에 따라 처리한다.
