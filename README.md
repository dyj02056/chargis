# Chargis (차지스)

> 전기차로 장거리를 갈 때 **"어느 휴게소(또는 충전소)에서, 몇 %까지, 얼마 동안"** 충전하면 되는지 차량 화면이 먼저 알려 주는 Pleos Connect용 장거리 충전 비서 앱

<img src="docs/screenshots/03-recommend.png" alt="주행 중 추천: 50km 앞 B 휴게소, 목표 50%, 다음 후보보다 5분 빠름" width="720">

현대자동차그룹 차량용 앱 개발 공모전 출품작입니다. 내비게이션 경로와 배터리 상태를 읽어 경로상 충전소 가운데 1순위를 고르고, 목적지까지 필요한 만큼만 충전하라고 안내합니다. 기본은 고속도로 휴게소이고, 졸음쉼터와 국도변·IC 근처·상업시설·공공시설 충전소도 대안 후보로 함께 비교합니다. 충전기 시간 제한까지 챙겨 주므로 충전이 중간에 끊기지 않습니다.

> 충전소 추천과 도착 배터리 예측은 이미 여러 EV 내비가 합니다. Chargis는 그 경로 위에서 **몇 %까지, 얼마 동안** 충전할지와 **충전기 시간 제한**까지 챙기는 비서입니다.

---

## 왜 만들었나

명절이나 주말에 고속도로로 장거리를 가는 전기차 운전자는 매번 같은 고민을 합니다.

| 문제 | Chargis의 답 |
|---|---|
| 휴게소 충전기가 붐벼서 기다려야 한다 | 출력, 가용 대수, 예상 대기를 함께 비교해 **덜 붐비는 휴게소**를 고르고, 휴게소가 모두 붐비면 **조금 벗어난 국도변·마트 충전소**까지 왕복 우회를 넣어 비교한다 |
| 시간 제한을 몰라서 충전이 중간에 끊긴다 | 충전을 시작할 때 **운영 규칙을 안내**하고, 제한 안에 목표에 닿을 수 있는지 미리 계산한다 |
| 몇 %까지 충전할지 판단하기 어렵다 | 목적지까지 필요한 에너지에 안전 마진을 더해 **"OO%까지만 충전"** 이라고 정해 준다 |
| 동승자가 언제 출발하는지 모른다 | 충전 화면에 **목표까지 남은 시간과 출발 예정 시각**을 크게 띄운다 |

## 기존 내비와 무엇이 다른가

경로상 충전소 추천, 도착 시 배터리 예측, 충전소 경유지 추가는 순정 EV 경로 플래너, 티맵 오토, Google Maps, Tesla 내비 같은 여러 내비가 이미 제공합니다. Chargis는 이 기능들을 다시 만드는 앱이 아닙니다. 내비가 짠 경로 위에서 **얼마나, 얼마 동안 충전할지**를 판단해 주는 비서 앱입니다.

| | 기존 EV 내비 | Chargis |
|---|---|---|
| 충전 목표 | 정차 지점과 충전 시간을 보여 주거나, 도착 잔량을 사용자가 정한다 | 목적지까지 필요한 에너지에 안전 마진을 더해 **"50%까지 충전"처럼 목표를 계산해 준다** |
| 충전기 시간 제한 | 다루지 않는다 | 제한 안에 목표에 닿는지 미리 계산하고, 못 닿으면 **10분·5분 전에 경고**하고, 끊기면 **다음 충전소를 다시 추천**한다 |
| 충전 중 화면 | 따로 없거나 차량 충전 메뉴에 맡긴다 | 목표까지·제한까지 남은 시간과 **출발 예정 시각**을 동승자도 읽게 크게 띄운다 |
| 혼잡할 때 | 자동으로 다른 충전소로 바꾸거나 사용 현황만 보여 준다 | **대기 시간 vs 도착 시 배터리**를 나란히 비교하고 운전자가 고른다 |
| 대상 | 모든 충전소 | **고속도로 장거리 이동**에 맞췄다. 휴게소·졸음쉼터를 먼저 고르고, 경로를 벗어나는 충전소는 **왕복 우회와 진출입 시간까지 셈해 확실히 나을 때만** 권한다 |
| 주행 중 안내 | 경로 안내 위주 | 충전소마다 한 번만 안내하고, 거절한 곳은 다시 말하지 않고, 버튼은 2개만 둔다 |
| 정보가 없을 때 | 표시 방식이 제각각이다 | 숨기지 않고 **"정보 없음"과 데이터 출처**를 표시한다 |

Chargis는 경로 안내를 기존 내비에 맡기고(`NaviPort`), 충전 판단만 맡습니다. 그래서 순정 내비와 경쟁하지 않고 그 위에서 함께 동작합니다.

> 비교는 2026년 10월에 공개 자료로 조사한 내용이며, 차종·버전·지역에 따라 다를 수 있습니다.

## 핵심 기능

| ID | 기능 | 설명 | 현재 상태 |
|---|---|---|---|
| F1 | 경로상 충전소 추천 | 경로상 충전소마다 주행(왕복 우회 포함)·도착 시각 기준 예상 대기·충전·들르는 시간을 더해 **목적지에 가장 빨리 도착하는 곳**을 1순위로, 대안 2곳과 함께 고른다. 한 번으로 못 가면 두 번째 충전소까지 계획한다. 후보는 고속도로 휴게소, 졸음쉼터, 국도 휴게소, 국도변·IC 근처 충전소, 상업·공공시설이며 휴게소·쉼터가 먼저다 | ✅ 구현 |
| F2 | 목표 충전량 코치 | 목적지(또는 다음 충전소)까지 필요한 SoC에 안전 마진을 더하고 5% 단위로 올려 "50%까지 충전"처럼 안내한다. 경로를 벗어난 충전소면 경로로 돌아오는 거리까지 채운다. 소비는 기온과 실측 전비로 보정하고, 충전 중에 ±5%로 바꿀 수 있다 | ✅ 구현 |
| F3 | 충전 시간 제한 알림 | 충전을 시작하면 "40분 제한"(데모 시나리오 값) 같은 운영 규칙을 안내하고, 목표까지·제한까지 남은 시간과 출발 예정 시각을 보여 준다. 제한 안에 목표에 못 닿으면 10분·5분 전에 "종료 시 약 N%"를 경고하고, 제한으로 끝나면 다음 충전소를 다시 추천한다. 곧 목표에 닿으면 5분 전에 이동 준비를 알린다 | ✅ 구현 (충전 시작은 버튼, 충전 중 SoC는 시뮬레이터 값) |
| F4 | 경유지 자동 추가 | 추천을 수락하면 해당 충전소를 내비게이션 경유지로 등록하고 경로를 다시 탐색한다 | 🟡 데모용 Fake 내비로 동작 (SDK 연동 예정) |

이 밖에 다음 기능을 함께 제공합니다.

- **혼잡 대안 비교:** 1순위 휴게소의 대기 시간이 20분을 넘으면, 대안 충전소와 "대기 시간 vs 도착 시 배터리"를 나란히 비교하는 카드를 띄웁니다.
- **휴게소 밖 충전소:** 졸음쉼터, 국도변·IC 근처, 마트·주유소 같은 상업시설, 공영주차장 같은 공공시설 충전소도 후보입니다. 경로를 벗어나는 곳은 **갔다 오는 거리(왕복)와 IC 진출입 시간(5분, 가정)** 을 도착 시각에 넣고, 휴게소·쉼터가 아니면 순위에 5분을 더해 휴게소를 먼저 고릅니다. 이용 가능 시간을 아는 곳은 도착할 때 닫혀 있거나 30분 안에 닫으면 뺍니다. 카드에는 이름 아래에 *"상업시설 · 왕복 5km 우회 · 10:00~22:00 운영"* 처럼 한 줄을 덧붙이고, 음성으로 *"I 마트, 경로를 벗어나 왕복 약 5킬로미터를 더 달립니다"* 라고 알립니다. 도심처럼 이런 충전소가 많은 구간에서는 20km마다 우회가 짧고 출력이 큰 2곳만 비교합니다. 휴게소만 보고 싶으면 설정의 **충전소 범위 → 휴게소·쉼터만**으로 끕니다.
- **경유지 변경 안내:** 수락한 곳보다 5분 넘게 빨리 도착하는 곳이 생겨 경유지를 바꾸면, 이전 경유지를 지우고 *"경유지를 바꿨습니다. B 휴게소 대신 C 휴게소. 목적지에 약 7분 빨리 도착합니다"* 처럼 이유를 말합니다.
- **시간 제한 정보 없음:** 제한이 없다고 확인한 충전기는 "없음", 확인하지 못한 충전기는 **"정보 없음"** 으로 나눠 표시하고, 충전을 시작하면 *"이 충전기의 시간 제한 정보가 없습니다. 충전기 화면에서 확인해 주세요"* 라고 알립니다.
- **이용 제한 충전소 제외:** 아파트·사업장·학교처럼 외부인이 쓰기 어려운 시설과 "입주민 외 이용불가" 같은 이용자 제한이 걸린 충전기는 후보에서 뺍니다.
- **음성 안내:** 모든 안내에 음성을 함께 내고 화면 아래에 자막으로도 보여 줍니다. 같은 문장은 반복하지 않고, 이미 안내했거나 거절한 충전소도 다시 안내하지 않습니다.
- **출처 표시:** 실시간 정보가 없으면 숨기지 않고 "정보 없음"으로 표시하고, 화면 상단에 데이터 출처(시뮬레이션, 직접 입력, 차량 데이터)를 표시합니다.

## 디자인: 통행권

Chargis의 화면은 **고속도로 통행권 한 장**을 모델로 했습니다. 출발할 때 표를 발권하고, 충전하는 곳마다 절취선이 있는 칸을 찍고, 도착하면 정산 영수증을 받습니다.

- **표 용지와 잉크:** 야간(기본)은 따뜻한 차콜 용지에 흰 잉크, 주간은 차가운 흰 감열지에 검은 잉크입니다. 시스템의 야간 모드를 따라 자동으로 바뀝니다.
- **도장 잉크 한 가지:** 코발트색은 지금 향하는 충전소, 충전소를 표에 찍는 동작(경유지로 수락), 도장에만 씁니다. 경고는 호박색이며 늘 그린 기호와 글자를 함께 씁니다.
- **글꼴:** 한글은 [Wanted Sans](https://github.com/wanteddev/wanted-sans), 거리·%·분·시각 같은 측정값은 [Geist Mono](https://github.com/vercel/geist-font)를 씁니다. 둘 다 SIL Open Font License 1.1이며 라이선스 전문은 [docs/licenses/](docs/licenses/)에 있습니다.
- **카드·그림자·이모지 없음:** 칸은 1dp 괘선으로만 나누고, 아이콘은 Compose로 직접 그렸습니다.
- **움직임은 최소로:** 주행 중에는 화면이 계속 움직이지 않습니다. 카드가 바뀔 때의 짧은 전환과 도장이 찍히는 순간만 움직이고, 기기에서 "애니메이션 제거"를 켜면 그것도 없앱니다.

디자인 결정은 [DESIGN.md](DESIGN.md)에, 제품 기준은 [PRODUCT.md](PRODUCT.md)에 정리했습니다.

## 실제 사용 화면

아래 화면은 앱에 들어 있는 **S1 시나리오(가상의 서울→속초 경로, 출발 배터리 60%, 210km)** 를 처음부터 끝까지 실행하며 캡처한 것입니다. 혼잡 화면은 S2, 충전 시간 제한 화면은 S3 시나리오입니다. 휴게소 밖 충전소는 S5 시나리오입니다.

> 03(추천)과 18(S5)은 휴게소 밖 충전소 지원 뒤에 다시 찍었습니다. 나머지는 그 전에 찍은 화면이라, 지금 앱에서는 정차 화면 비교 표 제목이 "앞으로의 휴게소" 대신 "앞으로의 충전소"이고 발권 화면 설정에 "충전소 범위"가 더 있습니다.

> 스크린샷은 일반 Android 에뮬레이터(태블릿, 가로 2560×1600)에서 찍었습니다. 오른쪽 위의 작은 `DEV` 꼬리표는 데모 진행용 개발자 오버레이이며 릴리스 빌드에서는 보이지 않습니다. 충전소 이름과 데이터는 모두 가상입니다. 화면의 "제한 40분"도 데모 시나리오에 넣은 가정 값이며, 실제 충전기의 제한 규칙은 운영사와 기기마다 다릅니다.

## 어떻게 계산하나

추천 엔진은 안드로이드 의존이 없는 순수 Kotlin 코드이며([`ChargeMath`](app/src/main/java/com/chargis/app/domain/engine/ChargeMath.kt), [`RecommendationEngine`](app/src/main/java/com/chargis/app/domain/engine/RecommendationEngine.kt)), 단위 테스트로 검증합니다.

```
socPerKm          = (1 / 전비) / 배터리 용량 × 100              // 1km당 쓰는 배터리 %
도착 SoC          = 현재 SoC − 거리 × socPerKm
필요 SoC(거리)    = 거리 × socPerKm × (1 + 안전 마진 15%) + 최소 도착 잔량 10%
목표 충전량       = 필요 SoC를 5% 단위로 올림 (상한 80%)
충전 시간         = 차종 충전 곡선이 있으면 SoC 0.25%씩 실제 출력으로 적분, 없으면 80% 이하 × 0.75 / 초과 × 0.35
소비 배율         = 기온·속도로 어림한 값에서 시작해 실측(최근 40km)으로 옮겨 감 → 전비 ÷ 배율
도착 시 대기      = 실시간 대기 × w + 시간대별 통계 × (1 − w),  w = 0.5^(도착까지 분 ÷ 45)
도착 SoC(충전소)  = 현재 SoC − (경로상 거리 + 편도 우회) × socPerKm
필요 SoC(충전 후) = 필요 SoC(편도 우회 + 남은 경로)                // 경로로 돌아오는 거리까지 채운다
목적지 도착(분)   = 주행(남은 경로 + 왕복 우회) + 예상 대기 + 충전 + 들르는 시간 3분
                    [+ 경로를 0.5km 넘게 벗어나면 진출입 5분] [+ 두 번째 충전소 몫]
순위              = 목적지 도착 + 위험 가산(도착 잔량 20% 미만, 시간 제한 위험)
                    + 휴게소·쉼터가 아니면 5분 이 가장 작은 계획
```

한 번 충전으로 목적지까지 못 가면, 뒤 충전소마다 첫 충전소 목표를 5%씩 바꿔 보며 **두 번 들르는 계획 중 가장 빨리 도착하는 조합**을 고릅니다. 느린 충전기에서는 덜, 빠른 충전기에서는 더 채우게 됩니다.

이용 가능 시간을 아는 충전소는 도착 시각부터 30분 동안 열려 있어야 후보로 둡니다. 모르면 열려 있다고 보고 화면에 시간을 표시하지 않습니다.

기본 차종 프로필(77.4kWh, 5.0km/kWh, 최대 150kW)을 쓰면 S1에서 다음처럼 계산됩니다.

1. 210km를 가려면 72.4%가 필요한데 현재 60%라서 충전이 필요합니다.
2. 90km 지점의 B 휴게소에 도착하면 약 36.7%가 남습니다.
3. B 휴게소에서 목적지까지 남은 120km에는 45.7%가 필요하므로, **50%까지 충전**하라고 안내합니다.

모든 수치는 가정 기본값이며 [`RecommendationConfig`](app/src/main/java/com/chargis/app/domain/model/Models.kt)에서 조정합니다.

- **포트와 어댑터:** 도메인과 UI는 SDK나 네트워크 클래스를 직접 쓰지 않습니다. 구현체 선택은 [`AppContainer`](app/src/main/java/com/chargis/app/AppContainer.kt)에서만 합니다.
- **데모 시뮬레이터:** [`ScenarioSimulator`](app/src/main/java/com/chargis/app/sim/ScenarioSimulator.kt)가 가상 시계 하나로 모든 Fake 포트를 움직입니다. 같은 시나리오는 항상 같은 결과를 냅니다.
- **주행/정차 전환:** `VehicleState.isDriving` 값 하나로 화면이 즉시 바뀝니다. 주행 중에는 스크롤과 텍스트 입력이 없습니다.
- **여행 복원:** 진행 중인 여행(단계, 수락한 충전소, 충전 세션, 이미 낸 알림)을 몇 초마다 기기에 저장해, 앱이 꺼졌다 켜져도 같은 표로 이어 갑니다.
- **공공 충전소 데이터:** `local.properties`에 `chargis.chargerApiKey`(data.go.kr 키)와 `chargis.usePublicChargerApi=true`를 넣으면 환경부 충전소 정보를 먼저 쓰고, 실패하면 번들 샘플로 넘어갑니다. 데모 경로는 가상이라 기본은 꺼져 있습니다. 어댑터는 시설 구분 코드(`kind`/`kindDetail`)로 휴게소·쉼터·상업·공공시설을 나누고, 급속이 아니거나 외부인이 쓰기 어려운 시설·이용자 제한(`limitYn`/`limitDetail`)이 걸린 충전기는 뺍니다. `limitDetail`은 충전 시간 제한이 아니라 **이용자 제한 사유**이므로, 시간 제한은 "1회 40분 이내"처럼 분 단위 제한이 분명히 적힌 경우에만 읽습니다. 이용 가능 시간(`useTime`)과 주차 요금(`parkingFree`)도 읽습니다. 공공데이터에는 시간 제한 항목이 없어서, 운영기관·시설 종류별로 확인한 규칙을 [`assets/charger_rules.json`](app/src/main/assets/charger_rules.json)에 출처와 함께 적으면 그 값을 씁니다(지금은 비어 있습니다). 이름에 "(서울방향)"처럼 방향이 적힌 휴게소는 진행 방향과 반대면 뺍니다. 공공데이터 충전소를 수락해도 데모 시뮬레이터가 그 자리에 경유지를 올려 정차·충전하고, 여행 복원도 됩니다.

```

├─ domain/   model/ engine/ session/   # 도메인 모델, 추천 엔진, 상태머신
```

1. 첫 번째 명령은 처음 한 번만 실행합니다. Android SDK와 에뮬레이터를 `%USERPROFILE%\Android\Sdk`에 설치하고, 가로형 태블릿 에뮬레이터 `chargis_wide`를 만들고, `local.properties`를 설정합니다. 실행하면 Android SDK 라이선스에 동의하게 됩니다.
2. 두 번째 명령으로 에뮬레이터를 켭니다.
3. 세 번째 명령은 **다른 터미널**에서 실행합니다. 에뮬레이터 부팅이 끝나기를 기다렸다가 앱을 빌드·설치하고 실행합니다.

**직접 빌드하기**

```bash
./gradlew assembleDebug testDebugUnitTest
```

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

- `local.properties`에 `sdk.dir`를 지정합니다. 이 파일은 커밋하지 않습니다.
- 키가 없어도 번들 샘플 데이터로 모든 기능이 동작합니다. 공공 충전소 데이터를 쓰려면 `local.properties`에 다음을 넣습니다. 이 파일은 커밋하지 않습니다.
  - `chargis.usePublicChargerApi=true`
  - `chargis.chargerApiKey=…`: data.go.kr 키. **개발용(debug) 빌드에만** 들어갑니다. 앱에 넣은 문자열은 APK에서 꺼낼 수 있어서, 배포용(release) 빌드에는 키를 넣지 않습니다.
  - `chargis.chargerApiBaseUrl=…`: 키를 대신 붙여 주는 중계 서버(프록시) 주소. 배포용 빌드에서 공공데이터를 쓰려면 이것을 지정합니다. 비우면 data.go.kr로 직접 부릅니다. 중계 서버 자체는 이 저장소에 없습니다.

**시나리오:** S1 기본, S2 명절 혼잡, S3 충전 시간 제한, S4 겨울 저녁(실측 전비 보정), S5 휴게소 밖 충전(붐비는 휴게소 대신 경로 밖 마트).

**데모 조작(디버그 빌드):** 오른쪽 위 `DEV` 꼬리표를 누르면 펼쳐지는 개발자 오버레이에서 배속(1×/5×/20×/60×), 일시정지, +10km/+30km 점프를 쓸 수 있습니다. 60× 배속이면 S1 전체를 약 3분 안에 재현할 수 있습니다.

## 현재 한계와 다음 단계

- **SDK 미연동:** Pleos Connect SDK(NaviHelper, Vehicle, TextToSpeech)가 아직 없어 모든 데이터는 시뮬레이터에서 나옵니다. SDK를 받으면 포트 뒤의 `Sdk*` 어댑터만 구현하면 됩니다.
- **충전 감지:** 충전 시작은 [충전 시작] 버튼으로, 충전 중 배터리 %는 시뮬레이터 값으로 받습니다. Vehicle SDK로 받을 수 있는지는 10/28 설명회에서 확인합니다.
- **실데이터 미검증:** 공공 충전소 API 어댑터는 있지만 실제 키로 호출해 응답 필드와 시설 구분 코드, 시도 코드(강원 51·전북 52)를 확인하지 못했습니다. 조회할 시도는 경로(직선)가 지나는 곳으로 고릅니다. 시간 제한 규칙표는 비어 있어 실제 데이터에서는 시간 제한이 "정보 없음"으로 나옵니다. 시간대별 혼잡 통계와 수동 SoC 입력은 아직 없습니다.
- **API 키:** 배포용 빌드에서 공공데이터를 쓰려면 키를 붙여 주는 중계 서버가 필요하지만 아직 만들지 않았습니다.
- **경로 투영:** 내비 경로 폴리라인이 없어 현재 위치→목적지 직선으로 경로상 거리와 우회 거리를 어림합니다. 반대 방향 휴게소는 이름의 방향 표기로 임시로 걸러 내지만, IC에서 실제로 들어가기 어려운 충전소는 가려내지 못하므로, 국도변·IC 근처 충전소는 실제 경로를 받은 뒤에야 믿을 만해집니다.
- **검증 환경:** 화면 확인은 일반 Android 에뮬레이터에서만 했습니다. Pleos Connect 에뮬레이터에서 다시 확인해야 합니다.

설계 결정과 가정은 [docs/DECISIONS.md](docs/DECISIONS.md)에, 확인이 필요한 항목은 [docs/OPEN_ISSUES.md](docs/OPEN_ISSUES.md)에, 전체 개발 계획은 [plan.md](plan.md)에 있습니다.
